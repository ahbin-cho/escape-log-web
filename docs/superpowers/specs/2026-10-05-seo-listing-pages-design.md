# 방탈로그 — SEO용 지역·브랜드 목록 페이지 설계

작성일: 2026-10-05 · 상태: 스펙 검토 대기

---

## 1. 목표

검색 유입을 늘린다. 지금 검색엔진이 색인할 수 있는 콘텐츠는 사실상 테마 상세(`/theme/[id]`)뿐이다.
`/region`은 클라이언트 컴포넌트라 크롤러가 받는 HTML에 테마 목록이 없다.

카탈로그 데이터로 **목록형 정적 페이지**를 추가해 "서울 방탈출 추천", "키이스케이프 테마" 같은
검색어를 받고, 테마 상세와 서로 링크해 내부 링크 구조를 만든다.

**성공 기준**

- 새 페이지의 HTML에 테마 목록이 그대로 들어 있다(자바스크립트 실행 없이 보인다).
- 새 페이지가 사이트맵에 올라간다.
- 목록 페이지 → 테마 상세, 테마 상세 → 목록 페이지로 서로 링크된다.

## 2. 결정 사항 (브레인스토밍 결과)

| 질문 | 결정 |
|---|---|
| 첫 스펙의 범위 | **지역 + 브랜드** 페이지. 장르·조건(`/best`) 페이지는 다음 스펙 |
| 세분화 단위 | **시도 + 브랜드만**. 지점·상권 단위 페이지는 만들지 않음 |
| 지역을 못 잡는 매장 | **코드에 매장→지역 보정표**를 둠. DB 스키마는 건드리지 않음 |
| 데이터 접근 | 카탈로그를 **한 번 읽어 메모리에서 묶음** |
| 주소 표기 | **한글 그대로** (`/region/서울`, `/cafe/키이스케이프`) |
| 렌더링 | 기존 테마 상세와 같은 **순수 SSG**, 갱신은 재배포 |

**범위 밖**

- 장르 페이지, 조건 페이지(입문·안 무서운·2인 등), 지점 페이지, 상권 페이지
- `catalog` 테이블 스키마 변경, 관리자 화면 변경
- 크롤러 스크립트 수정, 줄거리 재작성
- 테스트 러너 도입

## 3. 배경 데이터

로컬 수집분(약 299개, 실제 DB와 다를 수 있음) 기준:

- 시도별: 서울 112, 경기 54, 부산 21, 대구 16, 광주 15, 인천 8, 전북 6, 대전 6
- 브랜드: 10곳 (룸즈에이 60 ~ 포인트나인 9)
- **미분류 61개(약 20%)**: 매장명에 지역 단어가 없어 `regionFromText`가 못 잡는다.
  - 키이스케이프 이름형 매장 27개 (후즈데어, 메모리컴퍼니, LOG_IN 1·2, STATION, 더오름, 우주라이크, 무비무드, 에버랜드)
  - 비트포비아 던전101 4개
  - 셜록홈즈 30개 — 데이터에 지점명 자체가 없음

## 4. 라우트

| 경로 | 내용 | 생성 조건 |
|---|---|---|
| `/region/[region]` | 해당 시도의 테마를 브랜드별 섹션으로 묶어 표시 | 테마 3개 이상인 시도 |
| `/cafe` | 브랜드 목록 인덱스 (브랜드명 + 테마 수) | 항상 |
| `/cafe/[brand]` | 해당 브랜드의 테마를 지점별 섹션으로 묶어 표시 | 테마 3개 이상인 브랜드 |

- `[region]` 값은 `REGIONS`의 시도명, `[brand]` 값은 `cafe`의 첫 단어다.
- 세 동적 라우트 모두 `generateStaticParams`로 빌드 시 생성하고 `dynamicParams = false`로 둔다.
  목록에 없는 주소는 404가 된다.
- 한글 경로 파라미터는 페이지에서 `decodeURIComponent`로 풀어 쓴다.
- "미분류"는 지역 페이지를 만들지 않는다.

## 5. 구성 요소

### 5.1 `lib/catalog-server.ts` (신규)

서버 전용 카탈로그 읽기와 묶음 계산을 담는다. 페이지와 사이트맵이 모두 이 파일만 쓴다.

- `getAllThemes()` — `publicClient()`로 `catalog` 전체를 읽어 반환. React `cache`로 감싸
  한 번의 빌드/요청 안에서 중복 조회를 막는다. 실패하면 빈 배열.
- `brandOf(cafe)` — `cafe`의 첫 단어. 지금 `app/region/page.tsx`와 `ThemeCard`에 흩어진
  같은 로직을 이 함수로 모은다.
- `branchOf(cafe)` — 첫 단어를 뺀 나머지. 비어 있으면 빈 문자열.
- `themesByRegion()` — `Map<Region, Theme[]>`. `regionFromText(cafe)`가 null이면 제외.
- `themesByBrand()` — `Map<string, Theme[]>`.
- `MIN_THEMES = 3` — 페이지 생성 최소 테마 수.
- `listedRegions()`, `listedBrands()` — 최소 개수를 넘는 지역·브랜드 목록.
  `generateStaticParams`, 사이트맵, 링크 목록이 같은 함수를 써서 서로 어긋나지 않게 한다.

`Theme` 타입은 지금 테마 상세의 `ThemeRow`를 이 파일로 옮겨 공유한다.

### 5.2 `lib/region.ts` (수정)

- `CAFE_REGION_OVERRIDES: Record<string, Region>` 추가. 키는 매장명 접두어
  (예: `"키이스케이프 후즈데어"`).
- `regionFromText`가 키워드 검사 전에 보정표를 먼저 본다(텍스트가 키로 시작하면 그 지역).
- 대상은 3장의 키이스케이프 이름형 매장과 비트포비아 던전101이다.
  **각 매장의 실제 위치는 구현 시 공식 사이트에서 확인해 채운다.**
- 셜록홈즈는 지점 정보가 없어 보정 대상이 아니다. 미분류로 남고 브랜드 페이지에만 나온다.

이 변경으로 기존 `/region` 화면과 테마 상세의 지역 표시도 함께 정확해진다.

### 5.3 `components/ThemeList.tsx` (신규)

목록 페이지용 테마 항목 목록. 서버 컴포넌트다.

- 항목마다 테마명(→ `/theme/[id]` 링크), 매장, 장르, 난이도, 시간을 표시한다.
- 기존 `ThemeCard`는 클라이언트 컴포넌트이고 둘러보기용이라 재사용하지 않는다.
  스타일 클래스는 기존 카드와 맞춘다.

### 5.4 페이지 (신규)

`app/region/[region]/page.tsx`, `app/cafe/page.tsx`, `app/cafe/[brand]/page.tsx`.

공통 구성:

- `generateMetadata` — 제목, 설명, canonical, openGraph.
  - 지역: `서울 방탈출 추천 테마 112곳`
  - 브랜드: `키이스케이프 방탈출 테마 44곳 · 지점별 정리`
  - 설명에는 테마 수, 포함된 브랜드/지점 이름 몇 개를 넣는다.
- 빵부스러기 내비 + `BreadcrumbList` 구조화 데이터.
- 테마 목록 `ItemList` 구조화 데이터 (각 항목은 테마 상세 URL).
- 본문: 한 줄 소개, 섹션별 `ThemeList`.
- 하단: 다른 지역/브랜드로 가는 링크 목록, 취향 찾기(`/quiz`) 유도.

지역 페이지의 브랜드 섹션 제목은 `/cafe/[brand]`로, 브랜드 페이지의 지점 섹션에는
해당 지점의 지역 페이지로 가는 링크를 둔다.

### 5.5 기존 페이지 수정

- **`app/region/page.tsx`** — 지금의 클라이언트 화면 전체를 `components/RegionExplorer.tsx`로
  옮긴다(코드 변경 없이 이동). 페이지는 서버 컴포넌트가 되어 시도별 링크 목록
  (`listedRegions()` + 테마 수)을 HTML에 렌더하고 그 아래 `RegionExplorer`를 둔다.
  화면 동작은 그대로다.
- **`app/theme/[id]/page.tsx`**
  - 빵부스러기 2단계를 `/region` 고정에서 해당 지역 페이지로 바꾼다.
    지역 페이지가 없는 테마(미분류, 최소 개수 미달)는 지금처럼 `/region`으로 둔다.
  - 매장명을 `/cafe/[brand]` 링크로 바꾼다(브랜드 페이지가 있을 때만).
  - "같은 매장의 다른 테마" 섹션 추가: 같은 `cafe`의 다른 테마 링크, 최대 6개.
  - `BreadcrumbList` 구조화 데이터도 같은 경로로 맞춘다.
- **`app/sitemap.ts`** — `/cafe`, `listedRegions()`, `listedBrands()`의 주소를 추가한다.
  우선순위는 지역·브랜드 0.7, `/cafe` 0.6.
- **`components/SiteFooter.tsx`** — `/cafe` 링크 한 줄 추가(사이트 전체에서 진입 경로 확보).

## 6. 데이터 흐름

```
빌드 시
  getAllThemes()  ──(Supabase catalog 1회 조회, cache)
      │
      ├─ themesByRegion() ─ listedRegions() ─┬─ /region/[region] generateStaticParams
      │                                      ├─ /region 링크 목록
      │                                      └─ sitemap
      └─ themesByBrand()  ─ listedBrands()  ─┬─ /cafe/[brand] generateStaticParams
                                             ├─ /cafe 인덱스
                                             └─ sitemap
```

새 테마가 DB에 들어가면 재배포 시 목록 페이지에 반영된다(기존 테마 상세와 같은 정책).

## 7. 오류 처리

- DB를 못 읽으면 `getAllThemes()`가 빈 배열을 반환한다. 이때 동적 페이지는 하나도 생성되지 않고,
  `/cafe`와 `/region`은 빈 목록으로 렌더된다. 빌드는 실패하지 않는다(기존 테마 상세와 같은 동작).
- 목록에 없는 지역·브랜드 주소는 404.
- 잘못 인코딩된 경로 파라미터는 `decodeURIComponent` 예외를 잡아 404로 처리한다.

## 8. 검증

레포에 테스트 러너가 없고 이번에 들이지 않는다. 다음으로 확인한다.

1. `npm run build`가 성공하고, 빌드 출력에 `/region/[region]`, `/cafe/[brand]`가 SSG로 표시된다.
2. 빌드된 HTML(`.next/server/app/region/서울.html` 등)에 테마명과 `/theme/` 링크가 들어 있다.
3. `npm run start` 후 `/sitemap.xml`에 새 주소가 있다.
4. 존재하지 않는 `/region/없는곳`, `/cafe/없는브랜드`가 404다.
5. 보정표에 넣은 매장의 테마가 해당 지역 페이지에 나온다.
6. `/region` 화면이 이전과 같게 동작한다(지역 선택, 브랜드 필터).
7. `npm run lint` 통과.

## 9. 열린 사항

- 보정표의 매장별 실제 지역은 구현 시 확인한다(5.2).
- 한글 주소가 Search Console에서 정상 색인되는지는 배포 후 확인한다.
