# 방탈로그 사업 제안서 — "취향 데이터로 매장에 손님을 보내는 회사"

작성일: 2026-11-06 · 상태: 제안 (숫자는 모두 가정이며 검증이 필요합니다)

---

## 0. 한 줄 요약

지금 방탈로그는 **사용자에게 무료로 주는 좋은 앱**입니다. 다만 돈을 낼 사람이 정해져 있지 않습니다.
제안하는 방향은 이렇습니다.

> **방탈러에게는 계속 무료로 둡니다. 돈은 매장(공급자)에게서 받습니다.**
> 수익원은 "취향이 맞는 손님을 예약 페이지로 보내 준 실적"과 "그 손님들이 어떤 사람인지 보여 주는 데이터"입니다.

방탈출 취미는 시장이 작고 이용 빈도가 낮습니다(한 사람이 한 달에 몇 번 수준). 그래서 B2C 구독으로는 버티기 어렵습니다.
반대로 매장은 테마 하나에 큰 제작비를 들이고, 손님은 회전율로 받아야 합니다. **빈 시간대를 채우는 것**은 매장이 돈을 낼 만한 문제입니다.

---

## 1. 지금 가진 것 (코드에서 확인한 자산)

| 자산 | 위치 | 사업적 의미 |
|---|---|---|
| 취향 진단 16유형 + 공유·궁합 | `lib/quiz/*`, `/quiz`, `/match` | **유입 엔진.** 친구에게 공유하면 새 사용자가 들어오는 구조 |
| 테마 카탈로그 약 300개 + 지역·브랜드 SEO 페이지 | `/theme/[id]`, `/region/*`, `/cafe/*` | **검색 유입.** "강남 방탈출 추천" 같은 검색어를 받는 통로 |
| 취향 기반 추천 + 추천 이유 | `lib/quiz/recommend.ts` | **차별점.** 인기순이 아니라 "너에게 맞는 방"을 고름 |
| 예약 클릭 집계 (테마·매장·유입 경로별) | `lib/track.ts`, `/admin/clicks` | **영업 근거.** "이 매장에 N명을 보냈다"를 숫자로 보여 줄 수 있음 |
| 유형별 비율 집계 | `quiz_completions` | **데이터 상품의 씨앗.** 어떤 손님이 많은지 알 수 있음 |
| 광고 배너 슬롯 (`ad: true` 표시) | `lib/banners.ts` | 바로 쓸 수 있는 첫 수익 지면 |
| 기록·공개 후기·스포 수위 | `/records`, `/feed` | **잠금 효과.** 기록이 쌓일수록 다른 앱으로 옮기기 어려움 |

**결론:** 수익화에 필요한 부품(유입 → 추천 → 예약 클릭 → 집계)은 이미 거의 다 있습니다. 빠진 것은 **매장 쪽 화면과 가격표**입니다.

## 2. 누가 돈을 내는가

### 2-1. 고객 정의

| 고객 | 겪는 문제 | 우리가 주는 것 | 돈을 낼 의향 |
|---|---|---|---|
| **신규·중소 매장** (1~3지점) | 인지도가 없어 평일·낮 시간이 빔. 광고를 해도 누가 오는지 모름 | 취향이 맞는 손님에게 노출 + 예약 클릭 실적 리포트 | **높음** (핵심 고객) |
| **대형 브랜드** (다지점) | 신규 테마 출시 때 초기 후기·입소문이 필요 | 신규 테마 집중 노출, 유형별 반응 데이터 | 중간~높음 |
| **기업·단체** (워크숍, 동아리) | 인원·난이도·공포도에 맞는 곳을 찾기 번거로움 | 단체 맞춤 추천 + 예약 대행 문의 | 중간 (단가 큼) |
| **방탈러 (일반 사용자)** | 내 취향에 맞는 방 찾기, 기록 | 무료 | 낮음 → **돈은 받지 않음** |

### 2-2. 왜 매장이 우리에게 돈을 내는가 (영업 한 문장)

> "인기 순위에 묻히는 사장님 테마를, **그 테마를 좋아할 유형의 손님**에게만 보여 드립니다.
> 몇 명이 예약 페이지로 넘어갔는지 매달 숫자로 보내 드립니다."

기존 광고(SNS, 커뮤니티)는 넓게 뿌리고 결과를 알기 어렵습니다. 우리는 **누구에게 보였고 몇 명이 넘어갔는지**를 보여 줍니다.

## 3. 수익 모델 (도입 순서대로)

한 번에 다 하지 않습니다. 앞 단계에서 숫자가 나와야 다음 단계로 갑니다.

### 단계 1 — 실적 리포트로 영업하기 (지금 ~ 3개월)
- 지금 쌓이는 `reservation_clicks`로 매장별 **월간 리포트 PDF**를 만들어 무료로 보냅니다.
  - "지난달 방탈로그에서 사장님 매장 예약 페이지로 37명이 넘어갔습니다. 그중 60%가 '스토리 감성파' 유형입니다."
- 목적: 돈이 아니라 **"이 채널은 손님을 보낸다"는 인식**과 매장 담당자 연락처 확보.
- 필요한 개발: 클릭에 **유형 ID를 함께 기록** (지금은 테마·매장·경로만 기록함). 개인정보는 여전히 저장하지 않음.

### 단계 2 — 추천 상단 노출 (유료 슬롯) (3 ~ 6개월)
- **"취향이 맞을 때만" 노출하는 광고**입니다. 취향 점수가 기준 이상인 사용자에게만 해당 테마를 추천 상단에 보여 주고 "광고" 표시를 붙입니다.
  - 취향과 상관없이 아무에게나 띄우면 추천을 믿지 않게 되어 핵심 가치가 무너집니다. 이 원칙은 지켜야 합니다.
- 과금 방식 (택1로 시험):
  - **월 정액**: 테마당 월 3만~5만 원 (가정)
  - **클릭당 과금(CPC)**: 예약 페이지 이동 1건당 300~800원 (가정)
- 기존 `ad: true` 배너는 지역 페이지·브랜드 페이지까지 넓혀 **지역 타깃 광고**로 판매합니다.

### 단계 3 — 매장 파트너 센터 (SaaS) (6 ~ 12개월)
매장이 직접 로그인해서 쓰는 화면입니다.

| 기능 | 무료 | 유료 (월 2만~5만 원, 가정) |
|---|---|---|
| 내 매장·테마 정보 수정 (사진, 소개, 예약 링크) | ✅ | ✅ |
| 예약 클릭 수 (월 합계) | ✅ | ✅ |
| 클릭한 손님의 **유형 분포**, 시간대·요일, 유입 경로 | | ✅ |
| 공개 후기 모아 보기 + **스포 없는 요약** | | ✅ |
| "이 테마와 비슷한 경쟁 테마" 비교 | | ✅ |
| 신규 테마 출시 알림 (취향이 맞는 사용자에게) | | ✅ (건당 추가 요금) |

- 무료 단계로 매장이 정보를 직접 관리하게 만들면 **카탈로그 품질 문제(지역 미분류 20% 등)**도 함께 해결됩니다.

### 단계 4 — 예약 연동 수수료 (12개월 이후, 선택)
- 예약 시스템을 가진 매장과 제휴해 **실제 예약 완료 1건당 수수료**(예: 결제액의 3~5%, 가정)를 받습니다.
- 클릭이 아니라 결제 기준이라 가장 단가가 높지만, 매장마다 예약 시스템이 달라 개발·영업 비용이 큽니다. 단계 2·3이 돌아간 뒤 검토합니다.

### 보조 수익 — 단체·기업 매칭
- `/group` 같은 페이지에서 인원·예산·공포도·지역을 받고 **맞춤 코스(2~3개 테마)**를 추천합니다.
- 예약은 매장에 연결해 주고 **소개 수수료**를 받습니다. 건수는 적어도 한 번에 10명 이상이라 단가가 큽니다.

## 4. 성장 전략 — 사용자를 어떻게 모을 것인가

매장에 팔려면 **"우리 사용자가 많다"**는 숫자가 먼저 있어야 합니다. 유입 고리는 세 가지입니다.

1. **취향 진단 바이럴 (가장 강함)**
   - 결과 공유 → 친구가 퀴즈를 함 → 궁합 비교 → 다시 공유.
   - 추가 제안: **"우리 팀 궁합"** (3~6명 단체 궁합 + 단체에 맞는 방 추천). 방탈출은 원래 여럿이 가므로 공유가 자연스럽게 일어납니다.
   - 추가 제안: **시즌 이벤트** (할로윈 공포 진단, 연말 "올해의 방탈 결산" 카드).
2. **검색 유입 (SEO)**
   - 지역·브랜드 페이지 다음으로 **조건 페이지**("안 무서운 방탈출", "2인 방탈출", "입문 추천")를 만듭니다. 이미 설계 문서에서 다음 단계로 잡혀 있습니다.
   - 조건 검색을 하는 사람은 **예약 직전 단계**라 매장 입장에서 가장 가치 있는 손님입니다.
3. **기록 잠금 효과**
   - "탈출 N회 달성 배지", "연간 결산" 등으로 기록을 계속 쌓게 만듭니다. 기록이 많을수록 추천이 정확해지고, 다른 앱으로 옮기기 어려워집니다.

## 5. 숫자로 본 가정 (반드시 검증할 것)

아래는 감을 잡기 위한 **예시 계산**입니다. 실제 매장 수·전환율은 조사가 필요합니다.

| 항목 | 가정 |
|---|---|
| 월간 활성 사용자(MAU) | 12개월 후 3만 명 |
| 사용자 중 예약 클릭 비율 | 월 15% → 월 4,500 클릭 |
| 유료 노출 매장 | 40곳 × 월 4만 원 = **월 160만 원** |
| 파트너 센터 유료 | 30곳 × 월 3만 원 = **월 90만 원** |
| 단체 소개 | 월 10건 × 3만 원 = **월 30만 원** |
| **합계** | **월 약 280만 원** (12개월 시점, 가정) |

**해석:** 1인 사이드 프로젝트로는 의미 있는 수익이지만, 큰 회사가 되기는 어려운 규모입니다.
판을 키우려면 (1) 방탈출 → **보드게임카페·머더미스터리·전시형 체험**으로 범위를 넓히거나,
(2) 취향 데이터를 **콘텐츠 제작사(테마 개발사)**에 파는 방향을 고려해야 합니다.

**지금 바로 확인할 숫자 3개**

1. 지난 30일 예약 클릭 수와 매장별 분포 (`/admin/clicks`)
2. 퀴즈 완료 수와 공유 → 신규 유입 비율
3. 매장 5곳에 리포트를 보냈을 때 **답장 비율**과 "돈 내고 써 볼 의향"

## 6. 하지 말아야 할 것 / 조심할 것

| 위험 | 내용 | 대응 |
|---|---|---|
| **추천 신뢰 하락** | 광고 테마를 취향과 상관없이 띄우면 사용자가 떠남 | 취향 점수 기준 이상일 때만 노출, "광고" 표시 의무 (`ad: true` 원칙 유지) |
| **카탈로그 수집의 법적 문제** | 매장 사이트에서 정보를 가져오는 방식은 분쟁 소지 | 파트너 센터로 매장이 **직접 입력**하도록 전환, 요청 시 즉시 삭제 |
| **낯선 사람 매칭** | README 로드맵 5번 "같이 갈 사람 매칭"은 안전 사고·신고 대응 비용이 큼 | **뒤로 미룸.** 대신 "친구·팀 궁합"처럼 아는 사람끼리 쓰는 기능에 집중 |
| **후기 조작** | 매장이 돈을 내기 시작하면 후기 조작 유인이 생김 | 유료 매장도 후기 순서·숨김은 건드릴 수 없게 명시 |
| **작은 시장** | 방탈출만으로는 성장 한계 | 단계 3 이후 인접 체험 업종으로 확장 검토 |
| **개인정보** | 유형 데이터를 매장에 넘길 때 | 개인 단위가 아닌 **집계만** 제공 (지금 구조 그대로 유지) |

## 7. 90일 실행 계획

| 기간 | 할 일 | 끝났다고 볼 기준 |
|---|---|---|
| 1~2주 | 예약 클릭에 유형 ID 추가, 매장별 월간 리포트 자동 생성 | 리포트 1장이 버튼 한 번에 나옴 |
| 3~4주 | 매장 10곳에 무료 리포트 + 짧은 제안 메일 발송 (`CONTACT_EMAIL` 사용) | 답장 3곳 이상 |
| 5~8주 | "우리 팀 궁합" + 조건 SEO 페이지 3개 출시 | 퀴즈 공유 유입 20% 증가 |
| 9~12주 | 유료 추천 슬롯 시범 운영 (2~3곳, 첫 달 무료) | 1곳 이상 다음 달 유료 전환 |

**12주 후 판단:** 유료 전환 매장이 0곳이면 B2B 방향을 접고, 광고 배너 + 단체 소개 중심으로 가볍게 운영합니다.
1곳 이상이면 파트너 센터 개발로 넘어갑니다.

## 8. 정리

- **사용자에게는 계속 무료.** 진단·궁합·기록이 유입과 데이터를 만듭니다.
- **돈은 매장에서.** "취향이 맞는 손님을 보냈다는 실적"이 상품입니다.
- **신뢰가 핵심 자산.** 광고도 취향이 맞을 때만 보여 줍니다.
- **작게 검증하고 넘어간다.** 무료 리포트 → 유료 슬롯 → 파트너 센터 → 예약 수수료 순서로, 각 단계의 숫자를 보고 다음으로 갑니다.
